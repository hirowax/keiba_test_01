  - 満たすものが無ければ、3着内率が最も高い点を選ぶ。

## 2. 考え方（2026-11-07 外部レビューを反映）
- **過去のデータは、点の選定と診断に使う。有効性の確認は、選んで固定した後の将来のデータで行う。**
  - 過去の期間（2025-09-20〜2026-11-01）は、これまでの分析と点数の作り（加点の項目・点数）に使ってきた。そのため、前半・後半に分けても、後半は独立した確認にならない。9/12 以降という区切りでも、前半・後半のどちらも既に見た期間に入る。
  - 前半で選んで後半で確かめる計算は、参考（安定しているかの診断）として出すが、有効性の確認とは呼ばない。
- **複数の点から選んだ後の区間は、そのまま「95%の保証」とは扱わない。** 選んだこと自体で、選んだ点の成績は高めに出やすい。
- **不確かさは、開催日ごとのまとまりを単位にして見積もる。** 二項分布の区間（Wilson など）は、1頭ずつが独立という前提の方法で、同じ日・同じレースの馬のつながりを反映しない。そのため、選ぶときも確かめるときも、同じ方法（開催日単位のブートストラップ）を使う。

## 3. 決めること（案。推奨を先に書く）
### 3.1 使うデータ
- 選定と診断: タスク8の作り直しの後の、全期間（2025-09-20〜2026-11-01）の作り直した点数。
  - 品質の判定（`data_quality.race_quality_issues()`）を通ったレースだけ。
  - 照合は馬番と馬名の両方。
  - 取消・除外は分母から外す。中止・失格は分母に入れて3着以内でないとする。状態不明は件数を出して外す。
  - 作り直しで「当時の採点を再現できない」としたレース（タスク8の 2.1）は、別に件数を出して外す。
- 確かめ: 点を固定した日の次の開催日からの、本番の点数（作り直しではない）。

### 3.2 不確かさの計算（開催日単位のブートストラップ）
- 単位: 開催日。ある点 T について、その日の T 点以上の馬（分母に入る馬）全員を1つのまとまりとする。
- 計算: 開催日を、重複を許して同じ数だけ選び直す（その日の T 点以上の馬は全員まとめて入る）。選び直した集まりで3着内率を計算することを B 回（例: 10,000回）くり返す。その分布の 2.5% と 97.5% の値を区間とする。
- 乱数の種を決めて記録する（同じ入力で同じ結果になるように）。
- 区間を安定して計算できない場合は、その点を「保留」とし、採用しない。
  - 例: 対象の開催日が少ない、T 点以上の馬が1頭もいない日が大半、など。条件は 3.3 の最低条件で決める。
- レース単位の選び直しは、参考として並べて出す（開催日単位より幅が狭ければ、その旨を書く）。

### 3.3 候補の範囲・目標・最低条件・採用しない条件
- 候補の点: 3〜13点（今は3〜9点。CLAUDE.md の記録では実データの最高が13点のため広げる）。
- 目標: 3着内率の目標 R（数字はユーザーが決める）。
- 選び方の案（どれかを選ぶ）:
  - (a) **推奨**: 3.2 の区間の下限が R 以上になる、最も低い点を選ぶ。
  - (b) 区間の下限ではなく、3着内率そのものが R 以上の最も低い点を選ぶ。区間は参考として出す。
- 最低条件: その点以上の馬が30頭以上、かつ20開催日以上にまたがる。
  - **これは計算を始めるための最低の目安で、十分な精度の保証ではない**（CLAUDE.md のルール）。
  - 満たさない点は「保留」。
- **採用しない条件**:
  - 条件を満たす点が無い。この場合は🔥を出さない（今のように「最も高い点」を代わりに採用することはしない）。
  - 区間を安定して計算できない（3.2）。
- 参考（診断）:
  - 前半・後半に分けたときの、選んだ点の3着内率と区間。後半の結果で選び直すことはしない。
  - 回収率は選ぶ条件にしない。JRA 公式の払戻で参考として出す。
- 目標の数字の根拠に使う「でたらめに選んだときの3着内率」は、出しなおすなら、対象のレース・中止などの扱い・選ぶ頭数・重み付け（レースごとの平均か、全頭をまとめた率か）を決めてから計算する。
  - 2026-11-07 の案にあった 23.2% は、分母が着順のある馬だけで（中止・失格を結果を見た後に外している）、レースごとの単純な平均なので、根拠から外した（外部レビュー指摘）。

### 3.4 将来のデータでの確かめ（前向き）
使い始める前に、次を決めて記録する。
- 確かめに使う件数: 例として、固定した点以上の馬が N 頭、かつ M 開催日たまるまで（N・M はユーザーが決める）。
- 判定: その時点で、3.2 と同じ開催日単位の区間を計算する。
  - 区間の下限が R 以上: 確かめられた。
  - 区間の上限が R 未満: 目標に届かないと判断し、🔥を止める（基準を選び直すかは別に決める）。
  - どちらでもない: 件数が足りないとして、次の N 頭まで続ける。続ける回数の上限も決める。
- 途中で何度も見て止めると、偶然で判断しやすくなる。見る時点は前もって決めた件数のときだけにする。

### 3.5 実装
- `calibrate_threshold.py` の選び方を、決めた方法に合わせて直す。
  - 「最も高い点を代わりに採用」をやめる。
  - 毎回の自動の再計算を続けるか、決めた値に固定するかも決める。確かめの期間中は、固定する案を推奨する。
- サイトの「過去N頭中M頭 3着内」の表示は、決めた方法で計算した値だけにする。

### 数字の案（推奨を先に書く）
数字の根拠に使ったのは、次のとおり（成績は見ていない）。

1. **目標 R**
   - 推奨: **60%**（🔥の馬のうち、5頭に3頭は3着以内）。
   - **R は統計から導いた値ではなく、運用の目標として置く数字**（2026-11-07 外部レビュー）。
   - 理由:
     - 今の `calibrate_threshold.py` の 70% は、修正前のデータでどの点も届かなかった値で、根拠になる記録が無い。
     - 修正前のデータの参考値（9点以上 59%）は、誤った点数なので根拠にしない。
     - 60% は、利用の目安（「多くの場合3着以内」と言える水準）として、運用の判断で置く数字。データからの根拠ではない。
   - ほかの案: 50%（🔥の頭数は増えるが、外れも半分）、70%（届かない可能性が高く、🔥がずっと出ないかもしれない）。
2. **選ぶ期間**
   - 推奨: v5.2 で採点した最初の **20開催日**（3.3 の最低条件の20開催日と同じ）。年内の16日では足りず、2027年1月中ごろまでかかる見込み。

3. **確かめる期間の N・M（判定は1回だけ）**
   - 推奨（2026-11-07 外部レビューを受けて改めた案）: 選んだ点以上の馬が **N=200頭**、かつ **M=20開催日** の両方を満たした時点で、**最終の判定を1回だけ**行う。
   - 理由:
     - 200頭は、計画のときの見込み（上の参考の計算。分散1.5倍は確かめていない仮定）で、区間の幅が±8pt 程度になる数。この見込みは N を決めるためだけに使い、判定には使わない。
     - 20開催日は、日ごとのまとまりで計算するための最低限。
   - 集まるまでの見込み: 1日に選んだ点以上の馬が10頭なら20日（約2.5か月）。5頭なら40日（約5か月）。
4. **どちらとも言えないとき**
   - 推奨: 「保留」と報告して🔥は出さない。その確かめる期間のデータで判定をやり直さない。
   - 改めた理由（2026-11-07 外部レビュー）: 前の案の「200頭で判定し、どちらとも言えなければ400頭でもう1回」は、同じデータを2回見るので、ふつうの95%区間をそのまま使うと、誤って有効とする割合が5%より大きくなる。2回見るなら反復の判定に合わせた調整（例: 有意水準を2回に分ける）が要る。運用を簡単にするため、1回だけにする。
   - 保留の後にどうするか（基準を選び直す、新しい確かめる期間を前もって決めて集め直す、など）は、そのとき別に決める。保留の期間のデータを次の確かめる期間に混ぜない。
   - 途中で結果を見て止めることはしない。
5. **選ぶ期間の点の選び方**
   - 3.3 の (a) のとおり、開催日単位の区間の下限が R 以上の、最も低い点。
   - 選ぶ期間の20開催日では、どの点も下限が R に届かないことが多いと見込まれる（200頭に満たないため）。その場合の案（どれかを選ぶ）:
     - (i) **推奨**: 選ぶ期間では「3着内率そのものが R 以上で、30頭以上・20開催日以上の最も低い点」を選び、確かめる期間の判定（下限が R 以上か）で有効性を確かめる。選ぶ期間の区間は参考として出す。
     - (ii) 選ぶ期間の下限で選ぶ（(a) のまま）。届かなければ選ぶ期間を延ばす。延ばす上限も決める。

## 3.7 2026-11-13 の決定: 暫定の基準で始め、毎週見直す（成績は見ていない）

- 点数の式・目標の数字は変えない・決めない（目標 R などの数字は未決定のまま）。
- 手順:
  1. 2026-11-14 からの本番の点数・入力・品質の記録を保存する（今の仕組みのまま）。
  2. 2〜3週後に、品質の判定を通るレースで、点数の下限ごとに「対象の頭数・開催日数・3着内率・単勝回収率・複勝回収率」を並べた比較表を出す。除外したレースの件数と理由も並べる。これは🔥の馬の評価で、ワイドなど買い目全体の成績とは分ける。
  3. その表を見て暫定の値を決め、決めた日の次の開催から使う。少なすぎれば決めるのを延ばす。
  4. 毎週、その週に実際に使った基準の成績を積み上げる。変えるときは理由と適用日を残し、翌週から使う。過去の🔥や点数は書き換えない。1週の好不調だけで変えず、頭数・開催日数と累積の成績も見て判断する。毎週必ず変える必要はない。

- 過去の成績（取得できたレースの成績）は、暫定の値を選ぶ参考で、全レースでも同じになるとは扱わない。
