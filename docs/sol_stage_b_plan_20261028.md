## B0. 8頭打ち切りの診断（新規・使い捨て）

**新規**: `research/diag_shutuba_rows.py`

```
目的: shutuba.html の行数が8で切れる原因を特定する
手順: 1レースのみ取得し、以下を出力して比較する
  - domcontentloaded 直後の td.HorseInfo 行数
  - wait_for_selector("table") 後 + 固定待機後の行数
```

判定後の修正案（**別差分・承認後**）:

| 原因 | 修正箇所 | 内容 |
|---|---|---|

## B1. 研究データ生成（新規）

**新規**: `research/build_dataset.py`
**出力**: `research/artifacts/<run_id>/`（既存ファイルを上書きしない）
**形式**: 初版は CSV + JSONL（Parquet は新規依存になるため初版では使わない）

### 主キーと分離

```
主キー: race_id, horse_key, snapshot_id
  horse_key = horse_id があればそれ。なければ "umaban:<馬番>" + missing_reason
  snapshot_id = pickup_scores.json の generated_at（ファイル単位）
```

テーブルを4つに分離する（計画§4の「特徴量・結果ラベル・払戻・時点品質を分離」）。

| ファイル | 内容 |
|---|---|
| `features.csv` | 予想時点で保存されていた値のみ。3指数実数値・順位、スコア、加点内訳の各要素、予想時点オッズ・人気 |
| `labels.csv` | 確定着順、1着フラグ、3着内フラグ、連対フラグ、取消等の状態 |
| `payouts.csv` | JRA払戻（単勝・複勝）。確定オッズは別列にし、選定入力に使わない旨をヘッダコメントに書く |
| `quality.csv` | 時点品質。下表の列 |

### `quality.csv` の列（監査ラベルを項目単位で付与）

計画§A3の「全項目を一括して20260328以降なら安全と扱わない」に対応する。

| 列 | 値 |
|---|---|
| `provenance` | 当時保存 / 当日生成 / 遡及作成 |
| `rescored` | 0/1（`rescored_at` の有無） |
| `prev_source` | per_date_snapshot / global_horse_db / none |
| `prev_date_verified` | 0/1（prev_date < race_date） |
| `style_source` | global_no_date（現状は全件これ。未来混入を否定できない） |
| `odds_source` | prerace_saved / none |
| `pop_source` | prerace_saved / none |
| `horse_id_source` | shutuba_prerace / **reconstructed_from_results** / none |
| `umaban_gt8` | 0/1（8頭打ち切りの影響を受ける行の識別） |
| `field_size_source` | postrace_only（現状は全件これ） |

`horse_id_source = reconstructed_from_results` と `umaban_gt8 = 1` の行は、
当時保存データと**別集計**にする（計画§4の `reconstructed` フラグ要件）。

### 設定JSONに保存するもの

入力ファイルのハッシュ（`a1_file_inventory.csv` を参照）、コード版（git HEAD）、
対象期間、除外条件、目的変数、同点処理ルール。

### 対象期間（監査で確定した値を固定）

| セット | 定義 | 規模 |
|---|---|---|
| `primary` | 当時保存 ∩ オッズ保存期（20260711〜20261025） | 32日・371レース・候補494頭（オッズあり328頭） |
| `candidate_only` | 当時保存 + 当日生成の全期間 | 62日 |
| `excluded` | 遡及作成58日 | 研究から除外。理由を記録して保存する |

## B2. 検証（新規）

**新規**: `research/audit_dataset.py`

計画§4が要求する検証項目をそのまま実装する。

| 検証 | 内容 |
|---|---|
| 未来前走の拒否 | `prev_date >= race_date` の行を検出したら異常終了 |
| 未来脚質の拒否 | `style_source` が日付検証済みでない限り、脚質特徴量を `primary` セットから外す |
| 重複主キー | race_id × horse_key × snapshot_id の重複0件 |
| 欠損 | 0点・0倍・敗戦との混同がないこと（欠損は欠損として残す） |
| 取消 | 結果行なしと取消を区別できないため `scratch_state = unknown` を明示 |
| 同着 | 払戻定義とあわせて扱いを固定 |
| 少頭数複勝 | 複勝的中が「3着内」と一致しないケースを別ラベルにする |
| 払戻単位 | 100円単位の検算 |
| 誤結合 | 異なるレース間で馬番のみの結合をしていないこと |
| 将来データ追加の不変性 | 同じ `run_id` を再生成してハッシュ一致を確認 |

fixture は `research/fixtures/` に小さな合成データを置く。**既存実データは使わない・変更しない**。

## C段階に進む前の確認事項（ユーザー判断が必要）

1. **8頭打ち切りを先に直すか**。直さない場合、段階Cの比較は「馬番1〜8に偏った前走系ファクター」を
   含んだままになる。結果の解釈に制限がつく
2. **遡及作成58日を除外してよいか**。除外すると候補内評価は62日、市場比較は32日になる
3. **全頭モデルを諦めるか**。全頭オッズが揃うのは18レースのみ。計画§C3の「全頭市場最上位」基準は
   当面測れない。候補内比較に限定する案を提案する
4. **32日・候補328頭で段階Cを始めるか、収集を直して蓄積を待つか**。
   計画§C1は「データが少なく分割不能ならモデルを増やさず、監査と収集設計を納品して止める」と
   しており、32日では学習・調整・評価の3分割は実質不可能。**止める方を推奨する**
5. 既存ゲート（旧Phase Bの90開催日、`docs/anaba_research_log.md` の90日）は解除しない。
   本研究の準備と旧Phase Bの実行・本番採用は混同しない
