この時点で確認済みのこと（成績は見ていない）:
- 保存済みの近走平均の表 3,401 のうち 2,694 で、ページのトップ3とプログラムのトップ3が違う（2026-10-30 夜）。
- 保存した東京7R（10/31）の実ページでは、近走平均の順位が 1・2・2・4… で、「96*」の馬が1位。代わりの取り方（shutuba_submenu）で作った順位とも一致する。

## 1. 何が問題だったか

- netkeiba の近走平均の値は、5走分のデータが無い馬に「96*」のように「*」が付く。値は正しい平均値で、ページでは普通に順位が付く。
- `scraper.find_triple_top5_rows()` は値を `pd.to_numeric(errors="coerce")` で数字にするため、「96*」は読めずに捨てられ、その馬は近走平均のトップ3に入れなかった。意図した記録は無い。
- 同じ値の馬の扱いもページと違う。ページは同じ値に同じ順位を付けるが、プログラムは並べた順に1位・2位・3位を付け、3頭で打ち切っていた。
- サマリーの表示（`_get_topN()`・`_find_triple_top5()`）とサイトの単指数1位（`index.html` の `buildSingleTopMap`）にも同じ問題がある。

## 2. 新しい定義（成績によって変えない）

**「トップ3」は、各指数でページの「順位」が3位以内の馬とする。同じ順位の馬は全員入る。**
この定義は成績を見て選び直さない。成績が悪かった場合は、その候補を推奨・購入の対象にするかを別に検討する（定義は戻さない）。
取得や順位の作り方に誤りが見つかった場合は、実装を直す。

- 使う値は表の「順位」列（例: `1位`、`3位`）。
  - type=rank のページ: ページに書かれた順位。
  - 代わりの取り方（shutuba_submenu）: `make_rank_df` が付けた順位。同じ値は同じ順位で、次の順位は飛ばす。
- 順位の付け方の例:
  - 指数 100・100・90・80 → 順位 1・1・3・4。トップ3は最初の3頭。
  - 指数 100・100・100・90 → 順位 1・1・1・4。トップ3は最初の3頭で、90の馬は入らない。
  - 指数 100・90・80・80・70 → 順位 1・2・3・3・5。トップ3は最初の4頭。
- 「*」付きの値も順位どおりに扱う。0・マイナスの指数も順位どおり。
- 順位が「-」の馬（データ無し・未経験）は入らない。
- 3指数すべてでトップ3に入った馬（馬番で照合）を候補とする点は変えない。
- 表示も同じ考え方にする。
  - サマリーのトップ5は「5位以内の全員」にする。
  - 単指数1位は「順位が1位の全員」にする。
- 候補選び・サマリー・単指数1位は、同じ判定処理（順位列から N位以内の馬番を返す処理）を使う。サマリーで馬名照合している所も馬番照合にそろえる。

### 変える場所（承認後に実装）

- `scraper.py`: `find_triple_top5_rows()`、`_get_topN()`、`_find_triple_top5()`。記録する「順位」は並べた順ではなくページの順位にする。
- `index.html`: `buildSingleTopMap` の `[0]` だけを見る処理。サマリーの JSON に順位を入れ、1位の全員を表示する。
- `export_json.py`: サマリーの JSON に順位を含める（必要なら）。
- 候補の選び方が変わるので、スコア式（`SCORING_VERSION`）とは別に「候補の選び方の版」を pickup_scores.json に記録する
  （v6 は差し戻した版の名前として使ったので、同じ名前は使わない）。

### 追加するテスト

- 実ページ（`tests/fixtures/rank_202605041007_average.html`）で、96* の馬が1位でトップ3に入る。2位の2頭も入る。
- 自作の表で:
  - 3位に複数頭
  - 1位に複数頭（1・1・1・4）
  - 0・マイナスの指数
  - 順位「-」の馬
- 3指数の共通候補が馬番で決まること（同名の馬がいても混ざらない）。
- サマリーのトップ5・単指数1位が同じ判定処理の結果と一致すること。
- 代わりの取り方で作った順位が、type=rank の順位と一致すること。今ある当該コース（新潟3R）に加えて、近走平均（東京7R）でも確かめる。
- 限界: 実ページの例は2レースだけ。「3位に複数頭」の実ページは手元に無いので自作の表で確かめる。サイトの表示はテストが無いので、実装後に実際の画面で確かめる。

## 3. 過去データでの比較（参考の情報として報告する。定義の判断には使わない）

### 対象と使うファイル

- 期間: **2025-09-20 〜 2026-11-01**。
- 候補の比較と3着内率は、指数ファイルと結果ファイルの両方がある日を対象とする。
  - 指数: `output/YYYYMMDD.xlsx`（取り直さない）。この期間の日付名のファイルは122日分（2026-11-02 確認）。
    `output/` の xlsx は全部で123個あるが、残りの1つ `20260329_12R_preview.xlsx` は開催日の指数ファイルではないので使わない。
  - 着順: `output/YYYYMMDD/race_results.json`
- 回収率は、さらに払戻（`output/YYYYMMDD/payouts_jra.json`）がそのレース・券種で取れているものだけを対象とする。払戻の有無は回収率の対象選びにだけ使う。
- 無効レース（`output/YYYYMMDD/invalidated.json`）は、無効にしたレースがある日にだけ置く記録。ある日は読んで、載っているレースを外す。無い日は無効レースなしとして扱う（必須ファイルにしない）。
- 実行時に、使ったファイルの一覧（日付ごとの4ファイルの有無）を保存する。対象から外した日と理由も一覧にして報告する。

### 今までの選び方の再現

- 今までの選び方は、コミット `6f2ed8d` の `scraper.find_triple_top5_rows()` をそのまま呼んで再現する（書き写さない）。
- pandas 2.3.3 の `sort_values` の既定の並べ方は、同じ値の馬の順番が安定しない。そのため、同じ値のどの馬が選ばれるかも、この版の関数で決まった結果をそのまま使う。
- 再現した候補が、当時の `全場_3指数重複馬.csv` と一致するかを日ごとに確かめる。一致しない日は数と例を報告する。
- 一致しない場合は、「当時の候補」（当時の CSV）と「固定した旧コードで再計算した候補」を区別して報告する。比較には後者を使い、前者と混ぜない。

### 表の検査（候補を選ぶ前に行う）

まず、表の見出し行と馬の行を、構造で区別する。
- 保存済みの表には、列名の行（「順位・枠・馬番…」）のほかに、順位列に「5走前」が入る追加の見出し行がある（2026-11-02、`output/20261031.xlsx` と保存した実ページで確認）。
- 見出し行と認めるのは、この2種類の決まった形の行だけ。それ以外の行は馬の行として扱う。
- 順位が不正な馬の行を、見出し行として読み飛ばさない。

指数の表が次のどれかに当たるレースは、両方の選び方の対象から外す。理由ごとの件数を報告する。
- 指数の値が200以上（隠し値を読んでいた表）。
- 読めない指数。`scraper.classify_index_text()` で異常になる値。
- 馬の行の順位列が「N位」か「-」でない。
- 順位が値の大きさの順と合わない。
- 同じ表に同じ馬番が2回以上ある。
- 結果に載っている馬番が、指数の表に無い（表の一部が欠けている）。
  - 頭数の比較だけでは足りない。取消の馬の行が残り、別の馬の行が欠けると、頭数は一致してしまう。
  - 取消・除外・中止の馬は結果に載らないので、表にあって結果に無い馬番は、この検査では問題にしない。
- 3指数のどれかの表が無い。
- `invalidated.json` に載っているレース。

### 結果との照合

- **候補を選んでから結果と照合する。** 結果に無い馬を先に消して順位を繰り上げることはしない。
- 同じ馬とみなすのは、馬番と馬名の両方が一致したときだけ。
  - 馬名の表記差で許すのは、前後と途中の空白（全角・半角）の違いだけ。
  - あいまいな一致は使わない。
- 照合できなかった馬は、次の3つに分けて数を報告する。
  - 馬番は合うが馬名が違う
  - 馬番が結果に無い
  - その他
- 結果に無い馬の扱い:
  - 今の `scrape_results.py`（247行目付近）は、着順が数字でない行を捨てている。そのため結果に無い馬には、取消・除外と競走中止・失格が混ざっている。
  - 本来の扱いは状態ごとに違う。
    - 取消・除外: 出走していないので、3着内率の分母から外す。馬券は返還されるかを確かめる。
    - 競走中止・失格: 出走しているので3着内率の分母に入れ、3着以内ではない・不的中として扱う。
    - 状態が分からない: 取消などと推定せず、未確認として件数を記録する。
  - 比較を始める前に、候補の馬で結果に無い馬について、結果ページから状態を確かめる方法を試す。
    確かめられた馬は上の扱いにする。
  - 確かめられない馬が残る場合、その集計は「着順を取得できた馬だけの参考集計」と明記する。
    「100円ずつ買った場合の成績」を正確に表す集計としては扱わない。
  - 結果に無い馬の数は、状態ごと・候補の種類ごとに報告する。

### 比べるもの

候補の馬を3つに分ける。

| 分け方 | 内容 |
|---|---|
| 両方で候補 | 今までの選び方でも新しい定義でも候補 |
| 新しく候補 | 新しい定義でだけ候補（「*」の馬・同じ順位で入った馬） |
| 候補から外れる | 今までの選び方でだけ候補（同じ値の並び順でたまたま入っていた馬など） |

それぞれについて出す数字:
- 頭数とレース数。
- 3着内率（3着以内の頭数 ÷ 分母）。分母は着順のある馬と、状態を確かめた競走中止・失格の馬の合計。
  - 同じレースの複数の馬は独立した結果ではないので、信頼区間は出さずに頭数と率だけを示す。
- 単勝・複勝の回収率（100円ずつ買った場合）。
  - JRA 公式払戻（`payouts_jra.json`）がそのレースのその券種で取れているものだけで集計する。取れていないものは0円にせず、件数を報告する。
  - 取消・除外の馬は返還として投資にも払戻にも入れない。競走中止・失格の馬は投資に入れ、払戻は0円とする。状態が分からない馬は集計から外し、件数を報告する（上の「参考集計」の扱い）。
- 参考として、確定単勝オッズ × 100 円で出した単勝回収率も別に出す。
  - 1着の馬だけに当てはめる。
  - 公式払戻と一致するかを報告する。
  - 公式払戻の数字と混ぜない。
- 全期間に加えて、前半と後半（対象の開催日を日付順に半分に分ける）の数字も出す。

点数（pt）と🔥は比べない。修正前のデータは前走成績が別の馬の値なので、この比較では点数を正しく出せない。
点数と🔥の基準は、過去データの作り直し（残りのタスク8〜10）の中で、新しい定義で計算する。

### 結果の扱い

- 比較の数字は参考情報として報告する。統計的な差し戻しの条件は置かない。
- 「新しく候補」の成績が悪い場合は、その候補を推奨・購入の対象から外すかを、別の判断として検討する。
  - そのときも、その判断のための基準を先に決めてから評価する。
