## 2. 作業の進め方（ユーザーとのやり取りの決まり）
- 回答は日本語。挨拶・前置きなし、結論から。自作の略語・区分名（造語）を使わない。成績の報告は「単勝100円ずつ買ったら平均いくら返ったか」「何頭に1頭勝ったか」のような平易な言い方にし、表は2〜3列に絞る。
- 変更の前に、何を・なぜ・変更前後で何が変わるかを説明し、同意を得てから実行する。
- いつもの流れ:
  1. ユーザーが作業を指示する。
  2. 作業の後、ユーザーが「レビュー関連まとめて」と言ったら、外部レビュー（別の AI）に渡すまとめを書く。まとめには、変更の内容、確かめたこと、確かめていないこと、決めてほしいことを入れる。
  3. ユーザーが外部レビューの回答を貼り付ける。指摘を直すか、進める。指摘を受けたら、指摘の箇所だけでなく、同じ種類の問題がほかに無いかも点検する。
  4. ユーザーが「ok」「push して」と言ったら、取り込み・push する。push を聞いた後の「ok」は push の許可として扱ってきた。
- コード（とくに `scraper.py`・`race_pickup.py` など毎日 17:00 の採点に関わるもの）は、ブランチで作り、外部レビューの後に main に取り込む。
- 「残タスクは？」と聞かれたら、今の残りの作業を番号付きで短く出す。番号はその場限りのことがあるので、「3やって」と言われたら、どれを指すかを直前の一覧で確かめる。
- 意味の分からない語は推測しない（音声入力・変換の誤りがある。例: 「歌謡」は「火曜」のことだった）。分からなければ「〜という意味ですか」と聞き返す。

- **Cookie の有効性は期限日でなく実際の取得で確かめる**: 期限が1年近く残っていてもログアウトしていたことがある（2026-10-02、2026-11-13）。確かめるときは `scraper.preflight_premium_check` を新馬戦でない後半のレース（10R〜12R）で動かす。1R は新馬戦が多く、新馬戦は指数が無いので失敗しても Cookie 切れとは言えない。

- **推測で閉じない**: 異常に推測で説明を付けたら、確かめるまで終わりにしない。「未確認」と書く前に、調べればすぐ分かることは調べる。
