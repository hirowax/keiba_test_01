## 3. 方法（タスク7と同じ処理を呼ぶ）
- 計算はタスク7の `compare_index_top3_202611.py` で行う。書き写さない。
  - 指数のフォルダと日を指定するオプション（`--index-dir`・`--days`）を足す。
  - 省略したときの動作は今のままにする。
  - 足した後、省略して実行した結果が `research/index_top3_compare_202611/result_20261106.json` と一致することを確かめる（`run` の記録を除く）。
- 旧方式: タスク7と同じ、コミット `6f2ed8d` の `scraper.find_triple_top5_rows`。新しい定義: 今の `scraper.find_triple_top5_rows`。
- 分け方: タスク7と同じ「両方で候補」「新しく候補」「候補から外れる」。
- 表の検査・照合・分母・払戻の扱いは、タスク7（`docs/index_top3_definition_202611.md` の3章）と同じ。
  - 照合: 馬番と馬名の両方の一致だけ。
  - 取消・除外: 分母と投資から外す。中止・失格: 分母に入れ、3着以内でない・払戻0。状態不明: 推定せず件数を出す。

- 前半・後半の分け方はしない（6日しか無いため）。

## 5. 払戻が足りない場合（決めてもらうこと）
- タスク7と同じ問題がある。払戻は当時候補がいたレースにしかない可能性がある。
- 成績を出す前に、件数だけを出すモード（`--counts-only`）で「候補がいて払戻が無いレース」を数える。
- 案(a)（推奨。タスク7と同じ）: 足りないレースの払戻を JRA 公式から取る（`scrape_jra_payouts.py --races-file`）。取った後、1着の確定単勝オッズ×100 と単勝の払戻が合うかを確かめる。
- 案(b): 回収率は払戻があるレースの候補だけで出し、対象が偏っていることを明記する。
