- 確かに言える誤りはこの2つ。見出しのずれの結果、
  - 「このコースが得意な馬」の表は数えていない。

## 3. 読み取りの修正（案）
### 3.1 出走馬分析
- 表の中の見出しで種類を決める。数える種類を明示する。
  - 2026-11-07 に5レースで見た馬の表は6種類: このコースが得意な馬・この距離が得意な馬・この競馬場が得意な馬・今回の馬場状態が得意な馬・今回のレース間隔で実績がある馬・今回の調教評価で実績がある馬。
  - 今のコードの言葉にある「クッション」の表は、5レースでは見ていない。
- 馬ではないと分かっている表（枠順・脚質・騎手・調教師・種牡馬・母父・騎手の3種類）は数えない。**知らない見出しの表があれば取得異常にする。**
- 各馬は `div.Umaban_InBox` の `span.Umaban_Num`（馬番）・`WakuN`（枠）・短い名前から読む。出馬表の行と照らす（馬番の行がある、枠番が同じ、名前が先頭と同じ、同じ先頭の名前の別の馬がいない）。合わなければ取得異常。
- 同じ表に同じ馬番が2回あれば取得異常（二重に加点しない）。
- 表ごとの状態を分けて記録する。
  - 馬あり
  - 推奨なし（`span.Txt` が「推奨なし」）
  - 欄がない（data_top にその表が無い。9/12 のように欄全体が無い場合を含む）
  - 取得異常（読めない形・照合できない・重複・知らない見出し）
- 加点は今の定義（+1/条件）のまま、照合できた馬の登場数で数える。取得異常があるレースは、そのレースを品質の問題にする（加点を0にして黙って続けない）。

### 3.2 データ分析ピックアップ
