# 指数の表が無いときに、取得の時点で理由を記録する計画（2026-11-13 作成・未承認）

`scraper.py` が指数の表（近走平均・当該距離・当該コース）を取れなかったとき、今は理由を区別せずに「なし」と記録している。
これを取得の時点で分けて記録し、正常な表なしだけを正常として扱えるようにする。
2026-11-13 の外部レビューで、作成を進めてよい・分類は下の6つでよい、とされた。**この文書はまだ承認されていない。実装はしない。**

## 0. 今わかっていること（2026-11-13 にコードと保存ファイルで確かめた）
- `scraper.parse_speed_table` は、次のどれでも None を返す。呼び出し側は、例外も含めて、指数の取得の記録（`index_sources.json`）に「なし」と書く。
  - 表を待つ時間切れ（`PlaywrightTimeoutError`。警告を出して読み取りに進む）
  - ページに表が無い（`parse_rank_html` が None）
  - 表はあるが、先頭の列に「N位」の行が無い（`_is_valid_speed_df` が偽。「指数ランキング表ではないコンテンツ」と警告）
  - 取得中の例外（呼び出し側が「取得失敗」とログに出し、「なし」にする）
- 代わりの取り方（shutuba_submenu）は、3つとも None のときだけ試す。3頭以下の表は、ログアウト時のプレビュー版として捨てる。
- 11/6 のタスク3の取り直しで保存した指数のページ（`research/task3_index_refetch_20261106/pages/`。git の外）467ページのうち、表の無い扱いの76ページの中身:
  - **新馬戦 48ページ**: どれも「新馬戦にはタイム指数はございません」の文があり、表は0。
  - **全馬が値なしの表 28ページ**: 表はあり、出走馬が載り、値がすべて「-」「未経験」など。順位の列に「N位」が無いので `_is_valid_speed_df` が偽になり、今の読み取りでは捨てられて「なし」になる。障害戦（例: 2025-11-02 京都4R の3つ）と、初めてのコースの「当該コース」（例: 同日 東京8R）。
  - 76ページすべてで、canonical の URL がちょうど1つで、取りに行ったレースID と指数の種類（`race_id=…&type=rank&mode=…`）が入り、題名に日付（例: 2025年11月2日）とレース名（例: 東京4R）があった（どのレースのページかを確かめられる）。新馬戦の48ページでは、新馬戦の文がちょうど1つずつだった。
  - 正常なページにも「プレミアムサービスのご案内」「スーパープレミアムコースで限定公開中」の文がある。この文はログイン要求の目印にならない。
- 本番の記録（11/1・11/7・11/8）の「なし」は56件。新馬戦42件と、障害戦3レース分・11/7 福島1R・2R の「当該コース」14件。後者は、保存ページの「全馬が値なしの表」と同じ種類に見えるが、当時のページは保存していないので確かめられない。
- ログインの確かめ: `scraper.is_logged_in(page)`（マイページへのリンク）と、起動の時の `preflight_premium_check`（type=rank の表が取れるか）がある。

## 1. 分類（指数の表ごとに1つ）
| 分類 | 条件（すべて満たすとき） | 扱い |
|---|---|---|
| 正常な表なし（新馬戦） | 本人確認（下）が通る・ランキングの表が無い・「新馬戦にはタイム指数はございません」がちょうど1つある | 正常 |
| 正常な表なし（全馬が値なし） | 本人確認が通る・表がちょうど1つで、行が出馬表の馬（取消・除外を除く）と全頭そろう・値がすべて正当なデータ無し（`classify_index_text` が none）・順位の列に「N位」が無い | 正常。表は捨てずに記録し、結果の後の照合にも使う |
| 未公開 | 本人確認が通る・表もはっきりした文も無い、のうち、未公開と分かる表示があるもの | 未確認（問題には数えないが、件数を出す）。**表示の文言はまだ確かめていない**ので、確かめるまでは「未知のページ」に入る |
| ログイン要求 | `is_logged_in` が偽、またはログイン・会員登録への誘導だけのページ（目印は実ページで確かめてから決める） | 問題 |
| 時間切れ | 移動・表を待つところで時間切れになり、上のどれにも当たらない | 問題 |
| 通信失敗 | 移動・読み込みで例外が出た | 問題 |
| 未知のページ | 上のどれにも当たらない | 問題（正常にしない） |

- **表が見つからないだけでは、正常にしない**（2026-11-13 外部レビュー）。正常は、本人確認と、はっきりした表示（新馬戦の文、または全頭がそろった値なしの表）の両方があるときだけ。
- 本人確認: canonical の URL のレースID と指数の種類が、取りに行ったものと同じ（1つだけ）。題名のレース番号と開催場が、レース一覧と同じ。どちらかが合わなければ「未知のページ」。
- 新馬戦の文は、結果のクラス名とも照らす（文があるのに新馬戦でない、新馬戦なのに文が無い、は「未知のページ」）。照らすのは結果の後の照合でよい（取得の時点では、出馬表のクラス名で照らせるか、実装の前に確かめる）。

## 2. 記録
- `index_sources.json` の各レースに `no_table`（指数の種類ごと: 分類、取りに行った URL、開いた後の URL、題名、ページの SHA-256、保存先）を足す。`modes` の値（type=rank・代わり・なし・取得異常）は今のまま。
- 表の無いページは、`output/{日}/pages/index/{レースID}_{種類}.html.gz` に保存する（git には入れない。v5.2 のページの保存と同じ扱い）。保存に失敗したら、その表は「未知のページ」にする。
- 取り方が変わるので、`index_sources.json` に記録の版を足す（例: `NO_TABLE_REASON_VERSION`）。版が無い日は、今と同じく「未確認」。
- 全馬が値なしの表は、指数の表のファイル（`output/{日}.xlsx`）にも書く（今は捨てている）。候補選びには影響しない（値が無いので、どの馬もトップ3にならない）ことを、実装の前に確かめる。

## 3. 使い方
- 結果の後の照合（`index_table_check.check_day_against_results`）: 正常な表なしの2つは正常、未公開は未確認、ほかは問題。全馬が値なしの表は、表のある指数と同じく結果と照合する。
- 採点の品質の判定（`data_quality.race_quality_issues`）には、この変更では入れない。入れるかは、本番で分類の件数を見てから別に決める。
