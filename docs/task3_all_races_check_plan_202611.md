# 全レースの指数の表を照合するための変更案（タスク3。2026-11-07 作成。未承認）

**実装の前に、この案の承認を得る。** 成績は見ない（照合するのは馬番・馬名と、表の有無の理由だけ）。

## 1. 背景（`docs/incident_umaban_20261030.md` のタスク3）
- 本番の指数の表の照合（`index_table_check`）は、採点するレース（候補がいるレース）だけで行っている。表が欠けていて候補が出なかったレースは見つけられない。
- 結果の後に、その日の全レースの表を結果と照合する案は、外部レビューとユーザーが承認済み（2026-11-07）。
- 実装の前に分かった2つの穴:
  1. 毎日の `scrape_results.py` は、`pickup_scores.json` があれば、採点したレースの結果しか取らない（11/1 は8レース）。
  2. `index_sources.json` は、表が無いとき「なし」としか記録しない。新馬戦の正常な表なしと、取得失敗を区別できない。

## 2. 変更案
### 2.1 `scrape_results.py`: 結果を全レース分取る
- 今: `pickup_scores.json` があれば、そこにあるレースだけ。無ければレース一覧ページから全レース。
- 案: **いつもレース一覧ページ（`get_race_ids`）から全レースを取る。** `pickup_scores.json` にもあるレースは、レースIDが同じかを確かめる。違えば、そのレースは取らず、エラーとして記録して知らせる（どちらが正しいか分からないため）。
- 増えるページ: 1日あたり、採点しないレースの数（11/7 は36レース中17レース）。結果のページは1レース1ページ。血統のページは、新しい馬の分だけ増える。
- 影響:
  - `race_results.json`・`race_nonfinishers.json`・`race_conditions.json` に、採点しないレースも入る。
  - `calibrate_threshold.py`・`paper_trade.py`・`verify_results.py` は、採点したレースの分だけを読むので、変わらない（実装のときに呼び出し元をすべて確かめる）。
  - サイトの着順の表示は、採点しないレースのカードにも付くようになる（index.html はレース名で引くだけ）。

### 2.2 `scraper.py`: 指数の表が無い理由を記録する
- 今: `index_sources.json` の `modes` は「type=rank」「代わり(shutuba_submenu)」「なし」「取得異常」のどれか。
- 案: `modes` の値は変えない（`data_quality.py` などの読み手が変わらないように）。新しく `none_reasons`（指数ごと）を足し、「なし」の理由を記録する。
  - 「新馬戦（ページに『新馬戦にはタイム指数はございません』）」: 2026-11-06 の取り直しの48ページで見た文言。文字が完全に一致するときだけ。
  - 「表の待機がタイムアウト」
  - 「ランキング表ではないページ」（会員プランの表などが返ってきた）
  - 「表を読めない」（表が無い・行が無い）
  - 「取得中のエラー」（例外。メッセージを残す）
  - 全馬が値なしの表（順位がすべて「-」）は、表があるので「なし」にはならない（今と同じ）。
- 理由ごとに扱いを変えることは、この案ではしない（記録だけ）。新馬戦かどうかは、実際の記録がたまってから、結果の「新馬」の表記と照らして確かめる。

### 2.3 `verify_results.py`: 全レースの指数の表を結果と照合する
- 対象: その日の `output/{date}.xlsx` の全レースの表。結果（`race_results.json` と `race_nonfinishers.json`）があるレース。
- 照合: `index_table_check.check_index_tables` を、結果から作った出馬表の代わり（馬番→馬ID・正式名、取消・除外は取消の印）で呼ぶ。馬番と馬名の両方で照らす。
  - 取消・除外の馬: 表に無くてよい。あっても問題にしない（今の照合と同じ）。
  - 競走中止・失格の馬: 出走した馬として、表にあることを求める。
- 理由別に数えて `results_check.json` に保存する: 照合済み、表の欠け、余分な馬、馬名の違い、表が無い（2.2 の理由ごと）、結果が無い。
- 問題があれば、今と同じく終了コード1で LINE に知らせる。ただし、表が無い理由が「新馬戦」のレースは、知らせる対象から外す案（記録はする）。
- 限界（外部レビュー）: 結果の後に見つけるための検査で、当日の公開を防ぐ検査ではない。候補を選ぶ前の全レースの照合は、別の課題として残す。

## 3. テスト
- `scrape_results.py`: レース一覧と `pickup_scores.json` のレースIDが違う場合、片方にしか無い場合。
- `scraper.py`: 理由ごとの記録（新馬戦の文言・タイムアウト・ランキング表でない・例外）。実ページの新馬戦の文言は、2026-11-06 に保存したページの文字で作る（ページは公開しない決定なので、文言だけをテストに書く）。
- `verify_results.py`: 欠け・余分・馬名の違い・取消・中止・表が無い・結果が無い。
