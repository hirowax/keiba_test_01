# 穴馬フィルター最適化 検証計画書

**作成日**: 2026-05-04
**対象モデル**: このドキュメントを読んで実装・実行する別モデル
**目的**: 穴馬スコアリング v2 のベース設計はあるが、過剰選定と低的中率の問題があるため、複数フィルターの組合せで最適解を探す

---

## 背景（必読）

### 既に明らかになっていること
- 38日分・5+人気の馬 6070頭を分析済み
- 「前走1着 × 5+人気」が単独で **N=173, 勝率21.4%, 3着内32.9%, 単勝回収率539.9%** ← 強力
- ただし**先週末（5/2・5/3）は 13頭選定して 0/13 的中**という変動性
- 同一レースから複数頭選定されている問題あり（例: 5/2 東京5Rで3頭）

### v2 穴馬スコアの定義（既に決定済み・変更しない）
```
# 加点
+3: prev_rank == 1（前走1着）
+1: prev_rank == 2 or 3（前走2-3着）※前走1着とは排他
+1: prev_idx >= 80 AND prev_rank in (1,2,3)
+1: -2 <= hw_diff <= 2（馬体平行）

# 減点
-2: hw_diff <= -10（馬体大幅減）
-1: race_dist - prev_dist >= 200（距離延長+200m以上）
-1: 牝馬限定戦
```

実装済みスクリプト: `check_anaba_recent.py`（先週末用、参考実装あり）

## 検証タスク

### データソース
- **対象**: `output/YYYYMMDD/race_results.json` × `output/horse_db.json` × `output/YYYYMMDD/race_conditions.json`
- **対象日**: 38日分（2025-12-13〜2026-05-03）。`output/` 配下で `race_results.json` が存在する全日付。
- **3指数重複馬**: pickup_scores.json から取得して **除外** する（穴馬は重複馬以外を対象とする運用想定）
- **対象馬の条件**: `pop >= 5`（5番人気以下）、`is_triple == False`

### 実装すべきスクリプト

`analyze_anaba_filters.py` という新しいスクリプトを作成すること。

**要件**:
1. 既存の `analyze_anaba.py` の `load_all()` をベースに、3指数重複馬除外の anaba_pool を構築
2. 各馬に対して v2 穴馬スコアを計算（上記定義どおり、`extract_class()` などのヘルパは `analyze_anaba.py` から流用可能）
3. 「未勝利×前走1着」「3歳限定×前走1着」フラグも各馬に付与
4. 下記フィルター軸の全パターン × 主要組合せで集計
5. 結果を表形式でプリント（ROI降順）

### フィルター軸

#### 軸A: 1レースあたりの最大頭数
- A1: max 1（同一レースから最高スコア1頭のみ）
- A2: max 2（同一レースから最高スコア2頭まで）
- A3: 制限なし（現状）

#### 軸B: スコア閾値
- B3: score >= 3
- B4: score >= 4
- B5: score >= 5

#### 軸C: 単勝オッズ範囲
- C0: 制限なし
- C1: 5〜15倍（中穴）
- C2: 5〜30倍（中〜大穴）
- C3: 5〜50倍（大穴含む）
- C4: 10〜30倍（準人気除外）

#### 軸D: 特注パターン限定
- D0: 全候補
- D1: 「未勝利 × 前走1着」OR 「3歳限定 × 前走1着」のみ
- D2: 「未勝利 × 前走1着」のみ
- D3: D1 + 牝馬限定戦は除外

#### 軸E: 危険シグナルによる除外（減点ではなく完全除外）
- E0: 除外なし（減点のみ）
- E1: 牝馬限定戦の馬を完全除外
- E2: 距離延長+200m以上を完全除外
- E3: 馬体減-10kg以下を完全除外
- E4: E1+E2+E3 全部除外

### 集計内容

各フィルターの組合せに対して以下を出力:

| 列 | 内容 |
|----|------|
| filter | フィルター記述 |
| N | 選定総数 |
| N/day | 1日あたり選定数（38日で割る） |
| win | 勝利数 |
| top3 | 3着内数 |
| win_rate | 勝率% |
| top3_rate | 3着内率% |
| roi_win | 単勝回収率% |
| roi_place_est | 複勝回収率推定（place_odds が race_results.json にあればそれを使用、なければ単勝×0.4の概算）|

### 検証実行ステップ

#### ステップ1: 単一軸の効果測定
各軸を単独で適用した結果を表示。
- 軸A 単独: A1, A2, A3
- 軸B 単独: B3, B4, B5
- 軸C 単独: C0〜C4
- 軸D 単独: D0〜D3
- 軸E 単独: E0〜E4

#### ステップ2: 2軸組合せ
最も成績の良かった軸の値を組み合わせる。例:
- A1 × B3, A1 × B4
- A1 × C2, A1 × C3
- B4 × D1
- A1 × B4 × C2 など

#### ステップ3: 3軸以上の組合せ
ステップ2で良かった上位5パターンを軸を増やして検証。

#### ステップ4: 推奨セット決定
以下の基準を満たす組合せを「推奨」として最後にハイライト:
- N >= 30（38日でN30＝週1〜2頭程度の選定密度）
- top3_rate >= 30%
- roi_win >= 200%
- N/day <= 3（1日に3頭以下の選定密度）

複数候補があれば **「ROI最大」「3着内率最大」「バランス型（ROI×3着内率）」** の3つを提示。

## 重要な注意点

### バイアス防止
- **オッズベースの単純平均は外れ値で歪む**: 1頭の100倍勝ちが平均回収率を大きく押し上げる。**勝った馬を1頭ずつリストする**最終出力をつけること（外れ値検証用）。
- **小サンプル除外**: N<10 の組合せは「参考」表示にとどめ、推奨対象から外す。
- **38日は短期**: 結果はあくまで「過去38日でこうだった」という現状把握。汎化性能ではない。

### コード実装上の注意
- `analyze_anaba.py` の `load_all()` および `extract_class`, `extract_age_class`, `is_female_only` をそのまま import して再利用してよい
- `place_odds` フィールドは race_results.json に存在する（5/3データで確認済み）。`to_float(h.get("place_odds"))` で取得可能
- スコア計算は v2 定義（このドキュメント上部）に厳密に従うこと。新たな加点・減点項目は追加しない（最適化は **フィルター層のみ** で行う）

1. `race_pickup.py` または別モジュールに `score_anaba()` 関数を追加

これらは **別タスク** として後で行う。このスクリプトは **検証専用** であり、本番ロジックを変更しないこと。
