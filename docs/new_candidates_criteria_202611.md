# 「新しく候補」を推奨・購入の対象にするかの判断の基準（案・2026-11-06・未承認）

経緯: タスク7（`docs/index_top3_definition_202611.md`・結果 `docs/index_top3_compare_202611.md`）。
計画3章「結果の扱い」: 「新しく候補」を推奨・購入の対象から外すかは別の判断として検討し、その判断の基準を先に決めてから評価する。
この文書はその基準の案。**評価を始める前に承認を得て固定し、結果を見た後に書き換えない。** 変える場合は元の文を消さず、理由と日付を追記する。

## 1. 何を決めるか
- 「新しく候補」= 新しい定義（ページの順位で3位以内。同じ順位は全員・「*」付きも含む）では3指数の候補になり、旧方式（コミット `6f2ed8d` の選び方）では候補にならない馬。
- 決めること: この馬を、推奨（🔥・最注目馬・次点）とペーパートレードの買い目の対象に含めるか。
- 決めないこと: 定義（何をトップ3とするか）。定義は成績で戻さない。

## 2. 既に見たデータと、評価に使う期間
- 2025-09-20〜2026-11-01 の122日の比較の結果は、2026-11-06 に見た（全期間の3着内率: 両方で候補41.1%・新しく候補48.9%・候補から外れる33.3%）。
- **この122日は、この判断の評価に使わない。** 結果を見た後に作る基準を、同じデータで評価すると、基準を結果に合わせられてしまうため。参考の情報として文書に残すだけにする。
- 評価に使うのは、まだ見ていない期間: **2026-11-07 以降の開催日**。

## 3. 評価が終わるまでの扱い（決めてほしい）
- 案A（推奨）: 今のまま含める。新しい定義は 2026-11-02 に main に入り、11/7 の採点から本番で動く（候補選び・🔥・買い目は、新しく候補を区別していない）。外すにはコードの変更が要る。
- 案B: 評価が終わるまで外す（新しく候補には🔥を付けず、買い目の軸にしない）。旧方式の選び方を本番で動かすコードが要る。
- どちらにしても、実銭での購入は常に人間が判断する（CLAUDE.md）。

## 4. 評価の方法（実行前に固定する項目）

### 対象
- 期間: 2026-11-07 から、下の「評価を始める条件」を満たした最初の開催日まで。
- 使うファイル: `output/YYYYMMDD.xlsx`（指数の表）、`output/YYYYMMDD/race_results_all.json` か `race_results.json`＋`race_nonfinishers.json`（結果）、`output/YYYYMMDD/payouts_jra.json`（払戻）、`invalidated.json`（ある日だけ）。
- 新しく候補の見分け方: タスク7と同じ `compare_index_top3_202611.py` で、旧方式（`6f2ed8d`）を同じ指数の表に当てはめ直して分ける（本番に旧方式を入れる必要はない）。
- 除外: タスク7と同じ表の検査（表が無い・取得異常・ページの順位の食い違い・表の欠け・無効レース）。加えて、`pickup_scores.json` の品質の判定（`quality_issues`）があるレースも外す（推奨・買い目の対象にならないレースのため）。外したレースは理由別に件数を出す。

### 分母と照合
- タスク7と同じ: 候補を選んでから結果と照合する。馬番と馬名の両方の一致だけを同じ馬とする。取消・除外は分母から外す（馬券は返還）、競走中止・失格は分母に入れて3着以内でない・払戻0。状態が分からない馬は未確認として件数を出す。
- 払戻は JRA 公式。足りないレースは、成績を見る前に `scrape_jra_payouts.py --races-file` で足す。

### 主な指標と判断の規則
- 主な指標: 同じ期間の「新しく候補」と「両方で候補」の **3着内率の差**（新しく − 両方）。
- 不確かさの計算: **開催日を単位にしたブートストラップ**（開催日を復元抽出で選び直して差を計算することを10,000回。乱数の種を記録）。同じレース・同じ日の馬は独立でないので、馬ではなく開催日を単位にする。差の95%区間（2.5%点〜97.5%点）を出す。
- 判断の規則（評価の時に1回だけ当てはめる）:
  - 差の95%区間の上限が0より小さい（新しく候補が両方で候補より低いと言える） → 新しく候補を推奨・買い目の対象から**外す**。
  - それ以外 → **含める**（定義どおりの扱いを続ける）。
  - 境界の例: 区間が −8.0〜−0.1 ポイント → 外す。−8.0〜0.0 → 含める（上限が0は「0より小さい」に当たらない）。
- 回収率（単勝・複勝）は参考として出すだけで、判断に使わない（少数の高配当で大きく動き、必要な頭数が3着内率よりずっと多いため）。
- 推奨の段階（🔥・買い目の軸）に絞った成績も参考として出す（頭数が少ないので判断に使わない）。

### 評価を始める条件
- 「新しく候補」と「両方で候補」がどちらも、3着内率の分母で **300頭以上** になった最初の開催日の結果がそろった時点。
- 122日では新しく候補が1日あたり約11頭だったので、300頭はおよそ27開催日（3か月前後）の見込み。品質の判定で外れるレースがあると延びる。
- 300頭は評価を始める目安で、十分な証拠の保証ではない。区間が広ければ「含める」（今のまま）になる。

### 途中で結果を見ない
- 条件を満たすまで、新しく候補と両方で候補の成績を集計しない（件数・状態の確認だけはしてよい。タスク7と同じ扱い）。
- 途中で見た場合は、そのことと見た日付を記録し、評価の期間をその後に取り直すかをユーザーと決める。

### 報告
- 結果は別の文書（`docs/new_candidates_eval_YYYYMM.md`）に書く。使ったファイルの一覧と sha256、乱数の種、除外の理由別の件数、照合できない馬の件数を残す。

## 5. 決めてほしいこと
1. 評価が終わるまでの扱い（案A: 含める／案B: 外す）。
2. 判断の規則（開催日単位のブートストラップで、差の95%区間の上限が0未満なら外す）。
3. 評価を始める条件（両方とも300頭以上）。
4. 122日の結果を評価に使わないこと。
