# 「新しく候補」を推奨・購入の対象にするかの判断の基準（案・2026-11-06・未承認。外部レビュー1回を反映）

経緯: タスク7（`docs/index_top3_definition_202611.md`・結果 `docs/index_top3_compare_202611.md`）。
計画3章「結果の扱い」: 「新しく候補」を推奨・購入の対象から外すかは別の判断として検討し、その判断の基準を先に決めてから評価する。
この文書はその基準の案。**評価を始める前に承認を得て固定し、結果を見た後に書き換えない。** 変える場合は元の文を消さず、理由と日付を追記する。

## 1. 何を決めるか
- 「新しく候補」= 新しい定義（ページの順位で3位以内。同じ順位は全員・「*」付きも含む）では3指数の候補になり、旧方式（コミット `6f2ed8d` の選び方）では候補にならない馬。
- 決めること: この馬を、推奨（🔥・最注目馬・次点）とペーパートレードの買い目の対象に含めるか。
- 決めないこと: 定義（何をトップ3とするか）。定義は成績で戻さない。

## 2. 既に見たデータと、評価に使う期間
- 2025-09-20〜2026-11-01 の122日の比較の結果は、2026-11-06 に見た（全期間の3着内率: 両方で候補41.1%・新しく候補48.9%・候補から外れる33.3%）。
- **この122日は、この判断の評価に使わない。** 結果を見た後に作る基準を、同じデータで評価すると、基準を結果に合わせられてしまうため。参考の情報として文書に残すだけにする。
- 評価に使うのは、まだ見ていない期間: **2026-11-07 以降の開催日**。

## 3. 評価が終わるまでの扱い（運用の判断。統計の結論とは別）
- 案A（推奨）: 今のまま含める。新しい定義は 2026-11-02 に main に入り、11/7 の採点から本番で動く（候補選び・🔥・買い目は、新しく候補を区別していない）。外すにはコードの変更が要る。
- 案B: 評価が終わるまで外す。
- 評価の統計の結論が「判断保留」の間も、この運用の扱いを続ける（4章）。保留は「含めてよいと確かめた」という意味ではない。
- どちらにしても、実銭での購入は常に人間が判断する（CLAUDE.md）。

## 4. 評価の方法（実行前に固定する項目）

### 4.1 比べるもの（2026-11-06 外部レビューを受けて改めた）
決めるのは「推奨・買い目に含めるか」なので、全候補の3着内率ではなく、**実際に選ばれる馬・買い目**で比べる。
同じ将来のレースについて、次の2つを固定した規則で両方作って保存し、比べる。

| 呼び方 | 中身 |
|---|---|
| 含める場合 | 本番の採点・🔥・最注目馬・買い目そのもの（`pickup_scores.json`・`paper_bets.json`） |
| 外す場合 | 同じ採点結果から新しく候補を除き、同じ規則で🔥・最注目馬・買い目を作り直したもの |

- 外す場合を作れる理由: 各馬の点数は、ほかの候補がいるかどうかに左右されない（前走指数レース内1位の比較相手は、候補ではなく取消・除外を除く出走馬全員）。そのため、候補の一覧から新しく候補を除くだけで、残りの馬の点数は変わらない。買い目は `paper_trade.build_menus`（軸は点数1位の候補、`MIN_SCORE`＝8点以上）に、新しく候補を除いた一覧を渡して作る。
- 固定するもの（評価の期間中に変えない）: 採点の版 `SCORING_VERSION`（v5.1）、🔥の閾値（評価の開始時の `threshold_config.json` の値。評価の期間中に `calibrate_threshold.py` が値を変えても、評価では開始時の値を使う）、買い目の規則（`menu_rule`・`MIN_SCORE`・`BET_UNIT`）、候補の定義（`CANDIDATE_RULE_VERSION`）。どれかが本番で変わった場合は、その日以降を評価から外すか評価を打ち切るかを、成績を見る前にユーザーと決めて記録する。
- 外す場合の結果は、開催日ごとに別のファイル（`output/YYYYMMDD/variant_exclude_new_candidates.json`）に、作ったコードの版と一緒に保存する。作るスクリプトは承認後に実装する（本番のファイルは書き換えない）。
- 全候補の3着内率の比較（タスク7と同じ形）は、参考として出すだけにする。

### 4.2 対象
- 期間: 2026-11-07 から、4.5 の終了の条件まで。
- 使うファイル: `output/YYYYMMDD.xlsx`（指数の表）、`pickup_scores.json`（採点の記録）、`paper_bets.json`（含める場合の買い目）、外す場合のファイル、結果（`race_results_all.json` か `race_results.json`＋`race_nonfinishers.json`）、`payouts_jra.json`、`invalidated.json`（ある日だけ）。使ったファイルの一覧と sha256、判定に使ったコードの版（git のコミット）を、評価の入力として保存する。
- 新しく候補の見分け方: タスク7と同じ `compare_index_top3_202611.py` で、旧方式（`6f2ed8d`）を同じ指数の表に当てはめ直して分ける。
- レースの除外: **共通の `data_quality.race_quality_issues()` を、評価の時に呼んで判定する**（保存した `quality_issues` だけを見ない。採点エラーのレースには `quality_issues` が付かないため。2026-11-06 外部レビュー指摘）。採点の記録が無いレース（`pickup_scores.json` に無い・エラー）は「未確認」として外す。あわせてタスク7と同じ表の検査を当てはめる。外したレースは理由別に件数を出す。

### 4.3 分母と照合
- タスク7と同じ: 候補を選んでから結果と照合する。馬番と馬名の両方の一致だけを同じ馬とする。取消・除外は分母から外す（馬券は返還）、競走中止・失格は分母に入れて3着以内でない・払戻0。状態が分からない馬は未確認として件数を出す。
- 払戻は JRA 公式。足りないレースは、成績を見る前に `scrape_jra_payouts.py --races-file` で足す。

### 4.4 指標・計算方法・結論の出し方
- 主な指標: **🔥が付いた馬の3着内率の差（含める場合 − 外す場合）**。外す場合の🔥の馬は、含める場合の🔥の馬から新しく候補を除いたもの。
- 参考の指標（結論に使わない）: 最注目馬・次点、買い目の回収率（含める場合と外す場合の差）、全候補の3着内率の比較。回収率は少数の高配当で大きく動くため。
- 不確かさの計算（開催日を単位にしたクラスターブートストラップ）:
  - 対象の開催日の一覧から、同じ数の開催日を復元抽出で選ぶ。選んだ日の対象の馬は、その日の全員をまとめて使う（2つの場合で同じ日の選び方を使う）。
  - 各回の率は「選んだ日の3着以内の合計 ÷ 選んだ日の分母の合計」で計算する（日ごとの率の平均ではない）。差は、同じ回の2つの率の差。
  - 10,000回くり返し、差の 2.5%点〜97.5%点を95%区間とする。乱数の種を記録する。
  - 限界: 同じ日・同じレースの馬の関連は保てるが、別の日に同じ馬が走ることによる関連は扱えない。2つの場合の馬の条件（頭数・クラス・人気）の違いも解消しない。「関連を十分に扱えた」とはしない。
- 結論は3つに分ける（許容できる低下幅 δ を先に決める。案: δ＝5ポイント）:
  - 区間の上限が0未満 → **外す**（含めると悪くなると言える）。
  - 区間の下限が −δ より大きい → **含めることを支持**（含めても δ より大きくは悪くならないと言える）。
  - どちらでもない → **判断保留**（3章の運用の扱いを続ける）。
  - 境界の例（δ＝5）: 区間 −8.0〜−0.1 → 外す。−8.0〜0.0 → 判断保留（大きな悪化を否定できない）。−4.9〜+6.0 → 含めることを支持。−5.0〜+6.0 → 判断保留（下限が −δ ちょうどは「より大きい」に当たらない）。

### 4.5 終了の条件と、足りない場合の結論
- 評価は1回だけ行う。行う日は、次のどちらか早い方の後で、結果がそろった時点。
  - 含める場合の🔥の馬（分母）が 150頭以上、かつ対象の開催日が 40日以上になった日。
  - 評価の期限: 2027-06-30（それまでに条件を満たさなくても、この日までのデータで評価する）。
- 期限で評価して頭数が足りない場合も、上の3つの規則をそのまま当てはめる（多くは「判断保留」になる見込み）。
- 150頭・40日は評価を行う目安で、区間の精度を保証しない。122日では🔥の馬は少なく（現行の閾値9点。修正前のデータでの参考値は63日で134頭）、期限まで足りない可能性がある。
- 外す場合と含める場合の🔥の馬が同じ（新しく候補の🔥が0頭）の日は差が0として入る。

### 4.6 途中で結果を見ない・見た場合の扱い
- 評価の日まで、2つの場合の成績を集計しない（件数・状態・払戻の有無の確認はしてよい。タスク7と同じ扱い）。
- 途中で見た場合: 見た日付・見た内容・理由を記録する。**評価の期間と規則は変えない**（結果を見て期間を選び直せないようにする）。評価の報告に、途中で見たことを書く。
- 元の評価の記録（途中で見た分を含む）は消さない。

### 4.7 報告
- 結果は別の文書（`docs/new_candidates_eval_YYYYMM.md`）に書く。使ったファイルの一覧と sha256、コードの版、乱数の種、除外の理由別の件数、照合できない馬の件数、途中で見たかどうかを残す。

## 5. 決めてほしいこと
1. 評価が終わるまでの運用の扱い（案A: 含める／案B: 外す）。
2. 比べるものを「含める場合と外す場合の🔥の馬」にすること（4.1・4.4）。外す場合のファイルを作るスクリプトを実装すること。
3. 許容できる低下幅 δ（案: 5ポイント）と、3つの結論の規則。
4. 終了の条件（🔥の馬150頭以上かつ40開催日以上、期限 2027-06-30）。
5. 途中で見た場合も期間と規則を変えないこと。
6. 122日の結果を評価に使わないこと。
