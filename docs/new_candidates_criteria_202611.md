# 「新しく候補」を推奨・購入の対象にするかの判断の基準（2026-11-06 固定。外部レビュー2回を反映し、5章の項目をすべてユーザーが決定）

経緯: タスク7（`docs/index_top3_definition_202611.md`・結果 `docs/index_top3_compare_202611.md`）。
計画3章「結果の扱い」: 「新しく候補」を推奨・購入の対象から外すかは別の判断として検討し、その判断の基準を先に決めてから評価する。
この文書はその基準の案。**評価を始める前に承認を得て固定し、結果を見た後に書き換えない。** 変える場合は元の文を消さず、理由と日付を追記する。

## 1. 何を決めるか
- 「新しく候補」= 新しい定義（ページの順位で3位以内。同じ順位は全員・「*」付きも含む）では3指数の候補になり、旧方式（コミット `6f2ed8d` の選び方）では候補にならない馬。
- 決めること: この馬を、推奨（🔥・最注目馬・次点）とペーパートレードの買い目の対象に含めるか。
- **この評価で結論を出すのは🔥の選び方についてだけ**（2026-11-06 外部レビュー2回目）。🔥は9点以上、買い目の軸は8点以上で、🔥の比較に出てこない馬（8点の馬など）も買い目には影響する。買い目に当てはめるかは、この評価の結論を見たうえでの別の運用の判断とする。買い目の比較は参考として出す。
- 決めないこと: 定義（何をトップ3とするか）。定義は成績で戻さない。

## 2. 既に見たデータと、評価に使う期間

## 4. 評価の方法（実行前に固定する項目）

### 4.1 比べるもの（2026-11-06 外部レビューを受けて改めた）
決めるのは「推奨・買い目に含めるか」なので、全候補の3着内率ではなく、**実際に選ばれる馬・買い目**で比べる。
同じ将来のレースについて、次の2つを固定した規則で両方作って保存し、比べる。

| 呼び方 | 中身 |
|---|---|
| 含める場合 | 固定した設定で、採点結果の候補をそのまま使って作った🔥・最注目馬・次点・買い目 |
| 外す場合 | 同じ固定した設定で、採点結果から新しく候補を除いて作った🔥・最注目馬・次点・買い目。新しく候補は推奨・購入の対象から**完全に外す**（軸にしないだけではなく、◯・紐・全券種の組み合わせにも入れない。作った後に検査し、入っていれば止める） |

- **両方を同じ固定した設定から作る**（2026-11-06 外部レビュー2回目）。本番の出力（`pickup_scores.json` の🔥の表示・`paper_bets.json`）は本番の閾値で作られ、評価の期間中に閾値が変わり得るので、評価の「含める場合」には使わない。本番の出力は別に保存されたまま残す。
- 外す場合を作れる理由: 各馬の点数は、ほかの候補がいるかどうかに左右されない（前走指数レース内1位の比較相手は、候補ではなく取消・除外を除く出走馬全員。`prev_inputs.race_top1`）。そのため、候補の一覧から新しく候補を除くだけで、残りの馬の点数は変わらない。
- 固定する設定（評価の期間中に変えない）: 採点の版 `SCORING_VERSION`（v5.1）、🔥の閾値（評価の開始時の `threshold_config.json` の `ev_threshold`。開始時に値を記録する）、次点の幅（閾値−2〜閾値−1）、買い目の規則（`paper_trade.build_menus`・`menu_rule`・`MIN_SCORE`＝8・`BET_UNIT`）、候補の定義（`CANDIDATE_RULE_VERSION`）。本番で採点の版・候補の定義・買い目の規則が変わった場合は、その日以降を評価から外すか評価を打ち切るかを、成績を見る前にユーザーと決めて記録する（閾値は評価では固定するので、本番の値が変わっても評価は続けられる）。
- 2つの場合の結果は、開催日ごとに評価用の別のファイル（`output/YYYYMMDD/new_candidates_variants/{実行ID}.json`）に、作ったコードの版・固定した設定・頼っている関数の中身のハッシュ・入力の sha256 と一緒に保存する。入力・設定・コードが同じ記録があれば作らず、違えば別の実行として足す（前の記録を置き換えない）。本番のファイルは書き換えない。
- 固定の仕方（2026-11-06 外部レビュー3回目を反映）: 設定の値はスクリプトに書き込み、実行時のモジュールの定数を使わない。頼っている関数（買い目・候補選び・順位の判定）の中身のハッシュ、旧方式のファイル、開始時の閾値設定の写し（`research/new_candidates_eval_202611/threshold_config_start.json`）が変わっていたら、何も書かずに止める。入力の採点の版が v5.1 でなければ止める。
- 評価の対象かどうかは、レースごとに1つの判定（`eligible` と理由）で保存する。対象外: 採点の記録が無い（`pickup_scores.json` に無い・エラー）、品質の問題（実行時の `race_quality_issues()`）、指数の表が無い、候補の版が違う、採点の候補が指数の表から今の定義で選んだ候補と合わない。対象外のレースには🔥・買い目を作らない。
- 買い目を作る時の検査（外す場合）: 新しく候補を除いて候補が0頭になったレース、次の軸が `MIN_SCORE` 未満になったレースは、買い目なしとして理由を記録する。サマリー（`summary/YYYYMMDD.json`。◯と紐の選び方に使う）が無いレースも理由を記録する（含める場合も同じ）。
- 全候補の3着内率の比較（タスク7と同じ形）は、参考として出すだけにする。

### 4.3 分母と照合

### 4.4 指標・計算方法・結論の出し方
- 主な指標: **🔥が付いた馬の3着内率の差（含める場合 − 外す場合）**。外す場合の🔥の馬は、含める場合の🔥の馬から新しく候補を除いたもの。
- 参考の指標（結論に使わない）: 最注目馬・次点、買い目の回収率（含める場合と外す場合の差）、全候補の3着内率の比較。回収率は少数の高配当で大きく動くため。
- 不確かさの計算（開催日を単位にしたクラスターブートストラップ）:
  - 対象の開催日の一覧から、同じ数の開催日を復元抽出で選ぶ。選んだ日の対象の馬は、その日の全員をまとめて使う（2つの場合で同じ日の選び方を使う）。
  - 各回の率は「選んだ日の3着以内の合計 ÷ 選んだ日の分母の合計」で計算する（日ごとの率の平均ではない）。差は、同じ回の2つの率の差。
  - 10,000回くり返し、差の 2.5%点〜97.5%点を95%区間とする。乱数の種を記録する。
  - 限界: 同じ日・同じレースの馬の関連は保てるが、別の日に同じ馬が走ることによる関連は扱えない。2つの場合の馬の条件（頭数・クラス・人気）の違いも解消しない。「関連を十分に扱えた」とはしない。
- 許容できる低下幅 δ（3着内率のポイント）を、評価を始める前に決める。**2026-11-06 ユーザー決定: δ＝5ポイント**（2026-11-06 のこの会話でのユーザーの発言「δは5で」。受け入れる理由は述べられていない。**理由は結果を見る前に追記する。後から作らない。**）。 δ は「新しく候補を🔥に含めることで、🔥の馬の3着内率がこれだけ下がっても受け入れる」幅で、例えば δ＝5 は 40% から 35% への低下を受け入れるという意味になる。決めるときは受け入れる理由（例: 🔥の頭数が増えることとの引き換え）も書く。
  - 2026-11-06 追記（ユーザー承認）: 理由を書く期限を具体的にする。**評価の期間（2026-11-07〜）の成績を初めて集計する前、遅くとも比べられる条件がそろったかを確かめる時点まで**に書く。それまでに理由が無ければ、評価の成績を集計しない。
    - 理由は、122日の比較の結果（`docs/index_top3_compare_202611.md`）から作らない。5ポイントという値は、2026-11-06 に Claude が案として出したもの（122日の結果を見た後。根拠の計算や議論は無い）を、ユーザーが決めた。
    - 期限までに評価の期間の🔥の当たり外れを見てしまった場合は、見たことを記録する（期間と規則は変えない）。
    - 理由を考えるうちに値を変える場合も、評価の期間の成績を見る前に限る。元の値を消さず、変えた日付と理由を追記する。
- 結論は3つに分ける（2026-11-06 外部レビュー2回目で、重なりの無い形に改めた）:
  - 区間の上限が −δ 未満 → **外す**（許容幅を超えて悪くなると言える）。
  - 区間の下限が −δ より大きい → **許容幅の中であることを支持**（含めても δ より大きくは悪くならないと言える）。
  - どちらでもない → **判断保留**（3章の運用の扱いを続ける）。
  - 上限が −δ 未満なら下限も −δ 未満なので、2つが同時に当てはまることはない。
  - 「小さくても悪くなると言えれば外す」（上限が0未満で外す）形は採らない。採ると、δ の範囲の小さな低下でも外すことになり、δ を決める意味と食い違うため。
  - 境界の例（δ＝5 の場合の例）: 区間 −9.0〜−5.1 → 外す。−9.0〜−5.0 → 判断保留（上限が −δ ちょうどは「未満」に当たらない）。−4.9〜+6.0 → 支持。−5.0〜+6.0 → 判断保留。−4.0〜−1.0 → 支持（悪くなってはいるが許容幅の中）。
- 計算できない場合: 再抽出のある回で、どちらかの場合の分母が0になったら、その回は計算できない回として数える。計算できない回が全体の1%を超えたら、区間を出さずに判断保留とする。

### 4.5 終了の条件と、足りない場合の結論
- 評価は1回だけ行う。行う日は、次のどちらか早い方の後で、結果がそろった時点。
  - 下の「比べられる条件」をすべて満たした日。
  - 評価の期限: 2027-06-30。
- **比べられる条件**（2026-11-06 外部レビュー2回目で足した。数字は、同じ日のこの会話で私が出した案に、ユーザーが「1OKでpushして」と答えて決めた。外部レビューはこの数字を決めていない）:
  - 含める場合で新しく増えた🔥の馬（新しく候補で🔥の馬）: 30頭以上、かつ出てきた開催日が15日以上。
  - 外す場合の🔥の馬: 100頭以上、かつ出てきた開催日が30日以上。
  - 対象の開催日: 40日以上。
- 期限で評価する場合も、比べられる条件を満たさなければ、区間を計算しても結論は**判断保留**とする（期限が来たことだけを理由に結論を出さない）。
- 新しく増えた🔥の馬が0頭なら、2つの場合は同じで区間は0〜0になるが、新しく候補の成績は何も確かめていないので、上の条件により判断保留になる。
- **過去のデータでの別の評価**（2026-11-06 ユーザー決定）: タスク8で過去データの作り直しの手順が確かめられた場合に限り、2025-09-20 より前（比較の結果を見ていない期間）を、後から作り直したデータでの別の評価として足せる。
  - 2025-09-20〜2026-11-01 の122日は、比較の結果を見たので使わない。
  - 作り直しで再現できない入力（当時のオッズ・人気、各データ上位3頭・データ分析など）と、その扱いを、作り直しの前に書く。
  - この評価の規則（δ・3つの結論・比べられる条件）は同じにし、結果は将来のデータでの評価と分けて報告する。当時の実績とは呼ばない。
  - 足すかどうかと期間は、作り直しの手順を確かめた後、成績を見る前に決めて記録する。
  - （案・未承認。2026-11-06 外部レビュー3回目の推奨）主な判断は将来のデータの評価だけで行い、過去の作り直しのデータの評価は補助の確認にとどめる。将来のデータの結果を見てから過去の評価を足したり、2つのうち都合のよい方を採ったりしない。
- 条件の頭数・日数は評価を行う目安で、区間の精度を保証しない。122日では🔥の馬は少なく（現行の閾値9点。修正前のデータでの参考値は63日で134頭）、期限まで条件を満たさない可能性が高い。

- 途中で見た場合: 見た日付・見た内容・理由を記録する。**評価の期間と規則は変えない**（結果を見て期間を選び直せないようにする）。評価の報告に、途中で見たことを書く。
