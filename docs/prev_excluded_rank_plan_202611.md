# 案: 馬ページの前走の着順「除」（競走除外）の扱い（2026-11-06・未承認）

## 起きたこと
2026-11-07 の採点（2026-11-06 17:30〜の本番）で、2頭の前走データが「取得失敗」になった。

| レース | 馬 | 馬ページの最新の行 | 自前の結果（`race_results_all.json`） |
|---|---|---|---|
| 京都11R 1番 | モンドプリューム（2020103876） | 2026/09/12 ラジオ日本賞（202606040311）、着順「除」、人気・指数は空 | 中山11R 4番、状態「除外」 |
| 京都9R 2番 | ルトゥール（2021104929） | 2026/10/18 宝ケ池特別（202608040709）、着順「除」、人気・指数は空 | 京都9R 7番、状態「除外」。JRA 公式の払戻ページで返還馬番7番、「馬場入場後に疾病を発症したため競走除外」（`research/data_check_20261106/jra_pages_exclusion/`） |

- 原因: `prev_inputs.parse_results_table` が正常とする数字でない着順は、実ページで確かめた「中」（競走中止）だけ（`CONFIRMED_NONNUMERIC_RANKS`）。「除」は知らない表記なので、決まりどおり取得失敗にした。
- 影響: 2頭とも候補ではないので、点数・🔥・買い目は変わらない。ただし、2つのレースの前走指数レース内1位の判定が「保留」になり、候補の誰にも加点されなかった（比較に必要な値が分からない馬がいるため）。
- 「除」が競走除外の印であることは、2頭とも自前の結果の状態（除外）と、1頭は JRA 公式のページで確かめた。馬ページの行の元の文字は、前走データの記録（`output/20261107/prev_inputs/20261106T172952522067_721d173b.json`）に残っている。

## 考え方
競走除外の馬は、そのレースを走っていない（発走していない）。競走中止（「中」）は走り始めてから止まったので、扱いが違う。

## 案
- **案1（推奨）: 「除」の行を前走に選ばない。** 対象日より前の行のうち、着順が「除」の行を飛ばし、その前の行（実際に走った最新のレース）を前走にする。
  - 中4週・同距離・前走好走・前走指数・レース内1位の比較は、実際に走った最新のレースで計算する。
  - 飛ばした行は記録に残す（例: `skipped_rows: [{"date": "20261018", "rank": "除", "race_id": ...}]`）。
  - 飛ばした後に行が無ければ「前走なし」。
- 案2: 「除」を「中」と同じ扱いにする（状態「指数が空（着順が数字でない）」）。前走の日付・距離は除外になったレースの値になるので、中4週・同距離がそのレースで計算される。走っていないレースを前走として数えることになるので、推奨しない。
- 案3: 今のまま（取得失敗）。そのレースはレース内1位の判定が保留になり続ける。候補の馬なら、レースが品質の問題ありになり、🔥と買い目から外れる。

## 決めること・確かめること
1. 案1・2・3のどれにするか。
2. 「取消」の行（馬ページでの表記は未確認。「取」と見込んでいる）も同じ扱いにするか。実ページで表記を確かめるまでは、今のまま取得失敗にする（知らない表記を推測で正常にしない）。
3. 案1の場合、実装の前に2頭の馬ページを保存して、飛ばした後の行が正しく選べることを実ページで確かめ、テストの例（`tests/fixtures/`）に加える。
4. 取り方が変わるので `prev_inputs.PREV_FETCH_VERSION` を変える。採点の版（v5.1）と点数の式は変えない。
   - 「新しく候補」の評価（`docs/new_candidates_criteria_202611.md`）は、評価の期間中に採点の版・閾値・買い目の規則を変えない決まり。この変更は前走データの取り方の修正で、採点の式は変えないが、点数の入力は変わる。評価の記録に、変えた日と取り方の版を残し、変えた前後の日を分けて数えられるようにする（基準そのものは変えない）。
