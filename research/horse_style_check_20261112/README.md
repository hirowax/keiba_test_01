## 通過順の先頭の値が同じ地点か（設計 5章の4）
- `check_first_corner.py`: 保存した71ページ（取れた結果のすべて）で、馬の行の通過順（`td.PassageRate`）と、同じページのコーナーごとの通過順位の表（`table.Corner_Num`）を照らした。netkeiba にはアクセスしていない。結果は `check_first_corner.json`。
- 表の読み方: かっこの組は同じ順位、かっこの外は1頭ずつ、「*」付きの馬は組の中で先、「-」「=」は順位に関係しない。この読み方で、次のとおり合った。
- **完走した馬: 71レース・977頭のすべてで、行の値の数が、表でその馬が載っているコーナーの数と同じで、k 番目の値が表の k 番目のコーナーの順位と一致した。** 表の最初のコーナーはレースによって違う（1コーナー 27レース・2コーナー 6・3コーナー 38）。同じレースの完走した馬の先頭の値は、すべて表の最初のコーナーの順位だった。
  - これで、設計 3.1 の「完走した馬どうしで値の数が同じなら、先頭の値はそのレースで記録された最初のコーナー」は、この71レースでは確かめられた。直線のレース（新潟の芝1000m）はこの2日に無いので、確かめていない（使わないまま）。
- **中止の馬: 5頭（4レース）のうち3頭は一致したが、2頭は合わなかった。**
  - 11/8 福島4R の8番: 行は「10-11」（2つ）だが、表には4つのコーナーすべてに載っている（10・11・11・11）。先頭の値は表と一致。
  - 11/7 京都8R の2番: 行は空だが、表には4つのコーナーすべてに9番目として載っている。
  - 表は、中止した後も馬を並びに残すことがあるように見える。行の値と表のどちらが実際の位置かは分からない。
  - そのため、中止・失格の馬がいるレースは、今の規則どおり使わない（`build_horse_style.NONFINISHER_FIRST_CORNER_VERIFIED = False` のまま）。
- 失格の馬は、この2日にいなかった。
